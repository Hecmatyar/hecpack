# Coordination: chain of chats, sub-sessions

Injected into code sessions (the sections below) and into a session that coordinates others (`[coord]`).

## Chain of chats

- One task may run as a chain of chats. Every call re-reads the whole context, so a step at 400k costs about twice one at 200k, while a fresh session starts near its base context and pays off within some ten calls. At a natural break (an iteration accepted, a phase done) with real work still ahead, when the context is above the `freshSession` threshold in `.claude/hecpack/config.json`, propose continuing in a fresh session whose brief holds the goal, the current state, decisions made, options the user rejected, files and links, and the next step.
- Write the same brief to `tmp/handoff/<name>.md` at once and keep it current at each later break. After a compaction the hecpack hook lists the recent notes: read this task's and continue from it rather than from the summary. A session compacted twice proposes the fresh session at its next natural break whatever its size.

## Sub-sessions and the coordinator

- **Who coordinates.** A coordinator the platform runs (a project chat that starts the threads) splits the work; a session it started does its own piece and starts no sessions of its own. With no such coordinator, the session the task came to takes the role, but only when splitting pays.
- **When it pays.** Two or more independent pieces of real work (each M or bigger), split by files, that together would take this session past `freshSession`. A sub-session starts from its own base context (what `/hecpack:context` shows for a code session) and rereads the files it needs, so a piece that is not several times that stays here. An S task, a single M, pieces on the same files, and steps that need the previous step's result stay in this session. When it does not pay, say nothing about it and do the work.
- **Means, cheapest first.** A subagent (Agent tool) for a piece one brief and one report cover: research, a review, a self-contained change. A background session for a piece that needs a long context of its own: `claude --bg "Read <root>/tmp/handoff/<piece>.md and do it"`, with the user's permission mode.
- **Same folder or a worktree.** A worktree starts from the last commit: it has none of the uncommitted work and no `tmp/`. By default pieces run in this folder on disjoint files (one writer per set of files; an error in another piece's file is reported, not fixed). A worktree (`isolation: "worktree"`, `claude --bg --worktree <piece>`) only when the piece's base is committed and its files would collide. Briefs and reports stay in this checkout, named by absolute path (`<root>/tmp/handoff/...`), so a worktree reads and writes the same files. Where `claude --bg` does not exist, give the user that command to run in a terminal. At most 2–3 at a time; a shared export, theme or schema change runs first and alone.
- **Limits.** Every sub-session spends the same plan limits as this one, in parallel. After a rate-limit warning, or when the user said limits are tight, keep the work serial here and say so in one line. Each piece gets the cheapest model that fits: `agentModels` for agents, sonnet for mechanical pieces. A background session cannot ask the user anything, so a piece that needs the user's decisions or new permissions on the way stays in the foreground.
- **Each brief** (`tmp/handoff/<piece>.md`) holds: items with acceptance; owned and forbidden files; validation; «check your context after each part; past the threshold finish the part and write a handoff»; «when you stop, write `<root>/tmp/handoff/<piece>.report.md` once: first line `Status: done | partial | blocked`, then what changed, validation, open questions»; «start no sessions of your own». Where sessions can message each other, the sub-session also sends the coordinator one message when it stops.
- **While they run** the coordinator does not poll. It does its own part or ends its turn, and reads the state in one call with `/hecpack:coord` (the pieces, their sessions, worktrees and reports). It merges worktrees one at a time, with validation after each, and sends the closing check to `hecpack:checker`.
- **The coordinator stays short.** It does not retell a sub-session's report (one line with the link and whether the user must act), and keeps its state (pieces, sessions, open decisions, what the user must do) in `tmp/handoff/coordinator.md`. Past the `coordinatorClear` threshold, with no sub-session waiting on it, it asks the user whether to clear its context and continues from that file.
